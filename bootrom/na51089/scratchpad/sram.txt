na51089 bootrom -- SRAM and data layout
=======================================

The ROM uses three RAM windows.  None is cleared or initialised at reset (no
.data/.bss setup in start.S): every variable below is written by the boot
path that owns it before it is read.  Paths never run concurrently, so the
same bytes are reused (ETH frame buffers and secure-boot scratch overlap at
0xF07D0000).  The DRAM controller is not touched by the ROM itself; DRAM is
brought up only by the header register script (hdr_script_run).

Stack
-----

  sp = 0xF07D3000, set once at 0xb4 (`ldr sp, =0xF07D3000`), SVC mode,
  full-descending.  No other mode stack is set up (exceptions just spin).
  The stack therefore occupies 0xF07D0620..0xF07D2FFF at most; the deepest
  frames are hdr_script_run (0x88 B), rsa_read (0x108 B) and the nested
  fallback chain boot_fail -> next_boot_source -> X_boot -> ... which never
  unwinds (each failed source leaves ~0x50-0x80 B behind).

0xF07C0000..0xF07CFFFF  loader SRAM
----------------------------------

  0xF07C0000  32 KiB  Loader image area.  Header sectors beyond the first
                      512 B are assembled here (first sector copied from
                      0xF0800200, extra sectors read to 0xF07C0200) before
                      hdr_script_run; TFTP block n is stored at
                      0xF07C0000 + (n-1)*512 (n <= 64, so <= 32 KiB).  The
                      body itself goes to header+4, which for NT9856x
                      loaders is 0xF07C0000 too (LD9856xA.bin: entry
                      0xF07C0028).  Readers: flash_boot, sd_boot,
                      emmc_boot, eth_boot; secure_boot_verify reads
                      0xF07C0088 directly (header+0x88 bit29), whatever the
                      load address.
  0xF07C8000  4 x 2 KiB  Ethernet RX buffers, RX descriptor i -> 0xF07C8000 +
                      i*0x800 (eth_boot; address formed as
                      (i + 0x1E0F90) << 11)

0xF07D0000..0xF07D2FFF  scratch (per boot path) + stack
------------------------------------------------------

  Ethernet (eth_boot, eth_xmit):
  0xF07D0000  0x40   4 TX descriptors (EQOS normal format); eth_xmit uses
                     only the first, tail pointer 0xF07D0010
  0xF07D0040  0x40   4 RX descriptors, des3 = 0xC1000000 (OWN|IOC|BUF1V)
                     when recycled; tail pointer 0xF07D0070
  0xF07D0080  0x40   TX header buffer (Ethernet/IP/UDP or ARP, 0x2a B):
                       +0x06 (0086) source MAC
                       +0x10 (0090) IP total length (TFTP ACK: 0x0020)
                       +0x14 (0094) ARP opcode
                       +0x16 (0096) ARP sender MAC
                       +0x1a (009a) IP source / +0x1c (009c) ARP sender IP
                       +0x1e (009e) IP destination
                       +0x20 (00a0) ARP target MAC
                       +0x24 (00a4) UDP destination port
                       +0x26 (00a6) UDP length / ARP target IP
  0xF07D00C0  0x12c  TX payload: BOOTP (xid at 00c4, chaddr at 00dc,
                     options at 01b0..01bf) or TFTP RRQ / ACK

  Secure boot (secure_boot_verify, aes_cbc_decrypt, sha256):
  0xF07D0000  0x20   decrypted digest ('A') / RSA result tail ('R'),
                     compared with 0xF07D0060
  0xF07D0020  0x20   copy of header+0x2e0 (stored SHA-256)
  0xF07D0060  0x20   SHA-256 of the 32 KiB image
  0xF07D0080  0x20   AES IV (first 16 B used; 32 B copied from header+0x1e0
                     or +0x2c0 for 'S'; zeroed for 'A')
  0xF07D00A0  0x10   zeroed before hashing (unused afterwards, inferred)
  0xF07D0200  0x100  RSA modulus N (from header+0xc0)
  0xF07D0300  0x20   RSA exponent E (from header+0x1c0)
  0xF07D0400  0x100  RSA signature (header+0x1e0, byte-reversed)
  0xF07D0500  0x100  RSA engine output; digest expected at 0xF07D05E0
  0xF07D0600  0x20   SHA-256(N), compared with efuse words 0x14..0x1b ('C')

  0xF07D0620..0xF07D2FFF  free / stack (grows down from 0xF07D3000)

0xF0800000 window (second RAM; role inferred, only these bytes are used)
-----------------------------------------------------------------------

  0xF0800200  0x200  Header staging.  flash/SD/eMMC read the loader's first
                     512-byte sector here; ETH/USB/UART copy the first 0x28
                     bytes of the received image here.  Read back:
                     +0x04 (0xF0800204) load address, +0x24 (0xF0800224)
                     size, +0x38 (0xF0800238) script word.
  0xF0800400  4      bit31 = DMA reads straight to the destination (from
                     header+0x88 bit28); cleared by flash_boot/emmc_boot
  0xF0800420  ~0x24  USB descriptor bounce buffer (usb_get_descriptor)

Header in memory (summary; full table in bootrom.txt)
-----------------------------------------------------

  +0x00 entry  +0x04 load  +0x0c log  +0x24 size  +0x30 0xAA55  +0x34 poll reg
  +0x38 script word  +0x3c lane base  +0x40 script  +0x88 flags
  +0xc0 N  +0x1c0 E  +0x1e0 sig  +0x2c0 AES digest  +0x2e0 SHA-256
  +0x300..0x7fff encrypted area
