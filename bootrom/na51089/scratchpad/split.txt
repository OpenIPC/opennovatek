na51089 bootrom -- proposed split of the reconstruction (re/)
==============================================================

Goal: several people reconstruct in parallel without touching the same file.
Every ledger function (functions.txt, func_000..func_124) is assigned to
exactly one source file below; const data goes with its only user.  The
layout mirrors openhisilicon bootrom/hi3516av300/re (start.S + C +
regmap-*.h + umbrella header) but splits the C by subsystem, because this
ROM has ~7x the code of av300's.

Phase 0 -- shared headers, one person, before anything else
-----------------------------------------------------------
Written once from the scratchpad files, then frozen (changes by PR to the
owner only):

  re/na51089-regmap.h   umbrella: includes every regmap-*.h, REG32()/REG8()
                        accessors, block base addresses
  re/regmap-top.h       TOP 0xF0010000 (+0x1000 for 0xF0011000)
  re/regmap-cg.h        CG 0xF0020000 (clock-enable/reset bit names)
  re/regmap-pad.h       PAD 0xF0030000
  re/regmap-timer.h     TIMER 0xF0040000
  re/regmap-wdt.h       WDT 0xF0050000 (+ the 0xF0060000 unknown word)
  re/regmap-gpio.h      GPIO 0xF0070000
  re/regmap-uart.h      UART0 0xF0290000, UART1 0xF0300000
  re/regmap-spi.h       SPI flash controller 0xF0400000
  re/regmap-sdio.h      SDIO1 0xF0420000 / SDIO3 0xF0510000 (one layout)
  re/regmap-eqos.h      ETH MAC 0xF02B0000, DMA 0xF02B1000, glue/PHY
                        0xF02B3000, 0xF0FF0020
  re/regmap-crypto.h    AES 0xF0620000, HASH 0xF0670000, TRNG 0xF0680000,
                        RSA 0xF06A0000
  re/regmap-otp.h       OTP/efuse 0xF0660000 incl. the +0x50 boot-config bits
  re/regmap-ddr.h       0xC0001000 / 0xC0021000 (script ops 6/7 only)
  re/regmap-usb.h       USB 0xFF600000 / device block 0xFF600100
  re/sram.h             every address in sram.txt: struct g_eth, g_sd,
                        g_flash, g_uart, g_ep0, g_xfer, CBW/CSW, the
                        0xF0800200 header staging, loader header struct
                        (bootrom.txt), stack top
  re/bootrom.h          prototypes of every non-static function below,
                        boot-fail codes (K2..K10), BS strap codes, letters

Ownership hot spots (agree before starting)
-------------------------------------------
  * eth.c / net.c share one original function: agree the eth_hw_init /
    net_run interface (both static to the pair, or a shared eth.h).
  * check_and_run_loader is called with (fatal, hwsum_valid, hwsum) by six
    files; the hwsum convention (controller sum + n(n-1)/2, uint16) is
    computed by each caller -- keep that in the callers, not in start.S.
  * sram.h is the only place SRAM addresses appear; no file hard-codes
    0xF07Dxxxx itself.
  * Letters are printed by raw THR stores in most places (no FIFO wait) and
    by uart0_putc in uart_boot -- keep each call site's flavour, it is
    visible on the wire.

Suggested order of verification (QEMU / hardware)
-------------------------------------------------
  1. start.S + lib + timer + console + boot: "N", strap dispatch, "K"
     codes and the fallback chain with every source failing.
  2. flash.c + loader.c (NOR first): "NP?I/D" then "T" with a real loader.
  3. net.c/eth.c against the captured serial log quoted in functions.txt
     and a DHCP/TFTP host that serves loader.bin.
  4. uart_boot.c against an existing host-side NVT UART download client.
  5. usb, sd, emmc, secure last (need hardware or new QEMU models).
